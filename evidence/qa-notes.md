# Bounded data and security QA

Run date: October 16, 2026 (America/Denver). Node v24.14.0. This file describes the data/security audit; the root agent records actual browser observations separately.

- **PASS — live provider resolution.** `fixtures/cosmicspiderman.txt` was read in place, parsed into 84 entries / 100 physical cards / 84 distinct printing identifiers, and resolved through the application server and Scryfall HTTPS collection endpoint in batches of 75 and 9. Every entry resolved; zero mismatches, ambiguous entries or missing identifiers. The returned records contain 58 flavor passages and 27 resolved entries with no flavor text. No owner fixture was copied into `public/`.
- **PASS — explicit real commander.** The fixture's `[Commander{top}]` tag selected Cosmic Spider-Man, SPM 127, printing `f82f4013-7308-4917-9042-19a5909f2134`. Returned color identity was WUBRG. The main-deck union was not used.
- **PASS — actual governed provider search.** The application server executed `(f:commander id<=wubrg) (kw:Flying)` from `keyword-index-flying`. Scryfall reported 9,963 matching printings, returned 175 on page one, and the app adapter displayed 12. All first-page records passed the identity/Commander-status checks; no second page was fetched. The three actual request start gaps were 576 ms and 127 ms.
- **PASS — actual-printing module export.** A manually selected result, Aang, Air Nomad (TLE) 210, was added via the Clipboard module and changed to quantity 2. Export was `2 Aang, Air Nomad (TLE) 210`. The serialized immutable imported model was unchanged. This module smoke does not establish browser clipboard permission or OS clipboard behavior.
- **PASS — real distinct-printing evidence.** The actual search returned Aang, Swift Savior // Aang and La, Ocean's Fury (TLA) 204 with flavor and (TLA) 298 without flavor. Both were reported WU and Commander legal. Their UUIDs and the other bounded results are recorded in `provider-smoke.json`; these are observed provider results, not authored sample cards.
- **PASS — original-file preservation.** The acceptance suite re-hashed all 18 files enumerated in the pre-implementation audit, including four pinned sources, the owner deck, and all supplied visual assets. Every byte count and SHA-256 matched.
- **PASS — cross-module source contract.** The acceptance suite loads the actual catalog and checks all eight crosswalk mappings through the actual card sanitizer, printing resolver, detector and query builder. It exercises every named positive/negative/query fixture ID in `crosswalk.json`. Oracle text alone does not generate keyword evidence, and granted-ability keywords remain qualified as record-level evidence.
- **PASS — independent discovery state.** A complete deterministic stubbed-provider loop verifies import, Azorius identity, edition-specific absent flavor, excluded sideboard, literal repeated phrase, vetted search, session restore and print-aware export. Candidate evidence never joins imported flavor or mechanics.

Initial sandbox requests were blocked before reaching the provider (`EACCES` for localhost; `ENOTFOUND` for Scryfall). The same bounded smoke was rerun using the explicitly authorized network context and succeeded. These sandbox failures are not reported as provider downtime.

QA discovered and sent implementation owners three concrete data issues: catalog category spelling prevented detections; frontend collector matching disagreed with backend zero-padding normalization; malformed null faces produced a local error instead of a classified provider error. All three were fixed and covered by tests. The root agent also fixed a pending-search/context-change race using a generation guard. A generic-word summary counterexample (`One can always do anything.` / `One can always do something.` producing “always”, “can”, “one”) was reported for a small documented stopword correction before final sign-off.

Browser rendering, browser focus behavior, and actual browser copy are **NOT TESTED by this sub-audit**. No image licensing claim is made; the app uses a text-first result presentation without provider card-image requests.
